GET /meta.json

读取站点静态元数据

返回站点的 JSON 元数据文档。其中 live_monitoring: false 明确表示该文件是静态属性声明而非实时健康探针，调用方不应将此静态响应等同于整机或其他独立服务的实时监控结果。

响应属性说明 (Response Attributes)

schema_version string · required

当前静态元数据对象遵循的结构版本号，固定为 "1"。

service string · required

标识当前站点的服务形态，固定返回 "static-site"。

authentication string · required

标识接口认证要求，固定返回 "not-required"（无需认证）。

live_monitoring boolean · required

是否已接入实时监测数据流；当前固定为 false。

HEAD /meta.json

仅检查响应首部

发起 HEAD 请求可获取与 GET 完全一致的状态码与 HTTP 响应头，但服务器不会返回响应体字节。适用于本地诊断校验内容类型、文件字节长度及缓存首部。内容更新发布后，Last-Modified 与 ETag 会随实际静态文件自动变化。

HEAD Probe Example cURL 
curl --head https://{{DOMAIN}}/meta.json

注：响应首部中的时间戳与条件缓存标识以静态服务器实际返回为准，不硬编码固定过期时间。

STATUS CODES & LIMITS

HTTP 状态码与方法限制

本站仅提供静态资源读取，状态码由 Web 服务器根据静态文件存在性与请求方法直接生成：

200
读取成功 (OK)

请求路径存在且方法为 GET 或 HEAD，正常返回对应静态资源。

404
资源不存在 (Not Found)

请求的静态路径或隐藏路径不存在，返回标准 HTTP 404 状态。

403
方法不被允许 (Forbidden)

静态站点显式限制仅允许 GET 与 HEAD；发送 POST、PUT、DELETE 等写入请求将被拒绝（错误页不承诺为 JSON 格式）。
